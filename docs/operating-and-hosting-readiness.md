# Applicant Zero operating and hosting readiness

## Current operating model: ready for local use

Applicant Zero is designed to run on Rishi's Windows computer. The scheduled refresh runs when the computer is on and the user is signed in. The tracker, private profile, evidence and generated application material remain on that computer.

The current model is suitable for daily job discovery, preparation, confirmation recording, follow-up reminders and local backups.

## Local operating checklist

1. Run or schedule the daily refresh.
2. Check **Daily priorities** and review current roles.
3. Prepare only roles that pass Rishi's own final review.
4. Submit through the employer's website personally.
5. Save the employer confirmation and later complete the planned follow-up.
6. Create a dated private backup periodically.

## Hosting is not required yet

Cloud hosting is not needed for the current discovery, preparation and tracking workflow. It would move private candidate information off the computer and add recurring cost.

Do not host Applicant Zero until all of these are in place:

- encrypted secret and candidate-data storage;
- separate authenticated user account;
- encrypted backups and recovery testing;
- audit logs without credentials or application-answer content;
- clear source-by-source permission and platform-control review;
- an explicit user approval step before each application submission;
- monitoring, rate limits and a monthly cost ceiling.

## What must stay user-controlled

Regardless of where the system runs, it must not enter or store passwords, complete CAPTCHAs, answer identity or work-rights questions, create accounts, or submit applications without Rishi's direct action.

## Revisit hosting after evidence exists

Reassess a hosted version after three conditions are met:

1. The local workflow has been used for several real applications.
2. The discovery sources and tracker have operated reliably for several weeks.
3. The final résumé workflow is based on approved editable master documents.
